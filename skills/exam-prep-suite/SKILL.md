# 考公考编资料制作 · 总入口

一套面向考公 / 考编 / 事业单位 / 国企央企 / 辅警 / 社区专职的**印刷级资料生产线**。
用户通常只丢一句话（"XX考情"、"做几套模拟卷"），本技能负责**判线 → 路由 → 盯住交付铁律**，具体内容体系由对应子技能执行。

## 〇、这套技能怎么分层

```
              ┌──────────────────────────────┐
              │  总入口（本文件）             │
              │  判线 · 路由 · 交付铁律 · 环境 │
              └───────────────┬──────────────┘
                              │
        ┌──────────┬──────────┼──────────┬──────────┐
        ▼          ▼          ▼          ▼          ▼
     考情手册   备考讲义    模拟卷    真题还原   Word导出
   situation   prep-pdf   mock     restore    docx-export
        └──────────┴──────────┴──────────┴──────────┘
                              │
                              ▼
              ┌──────────────────────────────┐
              │  exam-pdf-render（共享渲染层） │
              │  HTML → 印刷级 PDF            │
              └──────────────────────────────┘
```

**关键认知**：五条内容产线**只负责写 HTML**；"HTML 变成能直接进印刷厂的 PDF"这件事，**全部统一走 `exam-pdf-render`**，不要各自重复踩坑。

## 一、路由：一句话需求走哪条线

| 用户原话（典型） | 产线 | 子技能 | 本质 |
|---|---|---|---|
| 「XX考情」「XX地区XX考试考情」「做份考情分析」 | 考情手册 | `exam-situation-handbook` | 帮考生**看懂这场考试**、判断值不值得报 |
| 「做一份XX备考资料 / 讲义 / 题本」 | 备考讲义 | `exam-prep-pdf` | 帮考生**学会怎么考** |
| 「做几套模拟卷 / 冲刺卷 / 押题卷」 | 模拟卷 | `mock-exam-paper` | 出**新题**（试卷 + 答案解析） |
| 「还原这份试卷 / 真题还原 / 把这张图做成试卷」 | 真题还原 | `exam-paper-restore` | 把**已有**真题/截图还原成卷 |
| 「转成Word / 导出docx / 要可编辑版」 | Word 导出 | `exam-docx-export` | 已有资料 → **可编辑 .docx** |
| 「排版 / 渲染PDF / 生成PDF / 目录页码」 | 渲染管线 | `exam-pdf-render` | 所有产线的**共同下游** |

**易混点（判错就整册重做）**：
- **考情手册 vs 备考讲义**：前者是"招考形势研究册"（公告机制、竞争比、薪酬趋势），后者是"学习材料"（知识点、答题框架）。数据源完全不同。
- **真题还原 vs 模拟卷**：前者是**还原已有题**，后者是**新命题**。
- 用户常把「试讲」（教师岗）与「结构化面试」（综合岗）混用 —— **每次必须用官方公告核对面试形式**再动笔。

## 二、全流程七步

1. **澄清口径** —— 用 `AskUserQuestion` 一次问完（覆盖范围 / 手册类型 / 时间跨度 / 篇幅深度）。
   - **若本系列已有同类先例**（如已做过"汕头辅警"再接到"揭阳辅警"），口径**直接沿用先例**，不要重复提问。
2. **调研** —— 只认**官网**（政府门户 / 招考网 / 单位官网）。用 `WebFetch` 抓公告页 + 提附件，`WebSearch` 补区情时政。
3. **定骨架** —— 从子技能的原型库选一个（考情手册有 12 种原型，模拟卷有配比模板）。
4. **定配色** —— 见第六节。**同批统一、跨项目换色、同系列沿用**。
5. **写 HTML** —— 封面**不写进 body**，单独用 `docs.json` 描述；CSS 变量管配色。
6. **渲染** —— 走 `exam-pdf-render`（A 线 Playwright 正式成品 / B 线无头浏览器轻量单文件）。
7. **巡检 + 目检 + 归档** —— 跑 `check.py`，再打开缩略图**逐页目视**（这一步是底线，不可省），然后清中间产物、交付。

## 三、交付铁律（违反即返工）

1. **一项目一文件夹**，文件夹内**只留最终 PDF**。脚本 / HTML / 临时图表全部放 `_build/<项目>/` 或 `/tmp/<项目>_work/`，交付前清干净。
2. **版式**：封面 + 目录（**带真实页码**）+ 分部分 / 分章节，严谨有逻辑，印刷级 A4。
3. **内容**：多维度、多角度展开；**教师岗**附当地学校简介与在用教材版本，**非教师岗不附**。
4. **美化**：多种图表混用（时间轴 / 雷达图 / 流程图 / 思维导图 / 对比表 / 环形图 / 柱状 / 折线），配色统一；**每个项目换一套风格配色**。
5. **页脚**：极小的整理署名 **「广东中公教研」** + 「第 X 页 / 共 Y 页」。
   > 2026-09-20 起由「广东中公小红书运营部」改为**「广东中公教研」**，此后所有批次沿用。
6. **红线**（交付前必 grep）：
   - 除广东中公外**不出现任何机构名**（华图 / 粉笔 / 京佳 / offcn / huatu / fenbi 等）
   - **不展示数据源**，不写"据XX网转载"
   - 公告原文里的**报名平台域名要模糊化**（`.gov.cn` 政府门户可保留，其余改写为"以公告原文为准"）
   - **无 AI 痕迹**（不写"本文由AI生成""仅供参考"之类的自我指涉）
   - 非公开数据（竞争比、薪资）可估算，但必须标注**"参考 / 测算"**

## 五、跨产线高频坑（每条都实测翻车过）

**渲染 / 分页类**

1. **CSS 的 `@page` margin 才是权威值** —— 只要 `style.css` 声明了非零 `@page` margin，`render.py` / `docs.json` 的 `margin` 参数就被顶掉。实测把参数从 17mm 改到 30mm，成品正文顶边（19.5mm）、页眉 y（16.5pt）、页脚 y（826.1pt）三个测量值完全不变。**改版心一律改 CSS，改参数不生效、也不报错**。随附 `style.css` 的默认配套是 `@page{size:A4;margin:18mm 15mm 16mm 15mm}` ↔ `margin={"top":"18mm","bottom":"16mm","left":"15mm","right":"15mm"}`，封面补偿 `.cover{margin:-18mm -15mm -16mm -15mm}` 与之绑定，改一边必须改另一边。反过来若写 `@page{margin:0}`，正文会满版出血而页眉页脚模板仍带 `padding:0 15mm` → 出现"页眉页脚正常、正文贴边"的错位。
2. **封面必须单独渲染再合并** —— Playwright 的 header/footer 模板对所有页生效，无法只跳过封面。
3. **`position:relative` 的提示框（`.tip/.warn/.key`）必须加 `page-break-inside:avoid`** —— 被跨页分片时 Chrome 会**按整页宽度**渲染分片，横向溢出并压住页脚。
4. **`.grid2/.grid3` 卡片组必须加 `page-break-inside:avoid`** —— 否则下一页顶部会渲染出**只剩边框的空卡**，极易漏检。
5. **章节强制分页会制造大量半空页** —— 内容型手册（区情册、资料册）把 `.chapter{page-break-before:always}` 改成 `auto`，实测 **37 页 → 27 页**且孤行页清零。
6. **孤行页修法优先级：内容搬家 > 删内容 > 拉伸留白。** 把上一页有空档的另一章小节整段搬过来（改编号即可），一次同时修好"溢出页"和"偏空页"，且不损失内容。
7. **分页密度**：`page-break-inside:avoid` 加在"题干+答案"整块上会在页底留大片空白 —— 改为只在**题干行**加 `page-break-after:avoid`，答案允许跨页，页数可压约 8%。

**目录 / 文本层类**

8. **目录 `data-s` 必须等于正文实际渲染出来的文本** —— `search_for` 在 PDF 文本层找不到就返回 0。二级条目改用**白色锚点**：`<span style="color:#fff;font-size:6pt">场次锚一</span>`。
9. **`display:none` 不进 PDF 文本层，搜不到** —— 要"不可见但可搜"只能用**白色文字**。
10. **目录里的标题文字会被 `search_for` 命中** —— 目录页放**白色**小字标记"导航页"，跨页时**开头结尾各放一个**。
11. **页眉 / 页脚的 `letter-spacing` 必须 < 1px**（已收到 0.7px）—— 字距大时 Chromium 会把一行拆成多个 text run，抽出来是"广 东 中 公 教 研"。**视觉完全正常**，只有文本抽取才发现。
12. **选项行"右溢 5—6pt"根因是 `letter-spacing` + 行尾全角空格** —— 把选项从纯文本改成 **flex 原子块**（`.opts{display:flex;flex-wrap:wrap;column-gap:1.7em;letter-spacing:0}` + `.op{white-space:nowrap}`），实测右溢归零且不复发。

**工程类**

13. **同一文件多个 Edit 必须串行提交** —— 并行会互相覆盖丢更新。批量替换改用 Python 脚本一次原子改写。
14. **PDF 转换不要和 `rm` 串在一条命令里** —— 转换失败会连带把源文件删掉。
15. **填充率巡检必须清 PNG 缓存** —— 脚本若带 `if not os.path.exists(png)` 判断，改版后旧 PNG 会让数字纹丝不动，误判"修改无效"。
16. **Python f-string 里禁止 ASCII 直引号** —— 中文引号一律用全角 `“ ”`，否则报 `SyntaxError` 且**行号指向下一个非 ASCII 字符**，极难定位。写完先跑 `ast.parse(src)` 预检。

**验收硬指标**

17. **收尾自检三条**：`check.py` 退出码 0（孤行页 0 / 越界页 0）；**全页填充率不低于 80%**；目录 `data-s` 全部命中。低于 80% 的页优先**补实质内容**（补一段实务提示、一张对比表），而不是拉行距。
