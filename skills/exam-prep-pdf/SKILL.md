# 备考资料 PDF 制作

把用户提供的试卷/考情，整理成"可交付的备考图书级 PDF"。适用于教师、综合岗、结构化面试、试讲、笔试等各类考编考公项目。

> **先分流**：若用户只要一句话「XX考情」「XX地区XX考试考情」，那是**考情手册**（招考形势研究册），请改用 `exam-situation-handbook` 技能。本技能用于**备考资料**（讲义/题本/答题框架）。两者渲染管线相通，但内容体系与数据源完全不同。

## 一、开工前必须澄清（否则极易做错方向）

1. **考试类型**：教师岗（试讲/说课）还是综合岗（结构化面试）？两者内容体系几乎不重叠。
   - 用户常把"试讲"与"结构化面试"混用 —— 务必用官方公告核对面试形式（如"结构化面试""无领导小组""试讲"）。
2. **学段学科**（教师岗）：决定教材版本与题本选题。
3. **机构署名与"不标注机构信息"的冲突**：若用户既要求页脚署名又要求无机构信息，确认署名形式（默认：页脚浅灰小字）。
4. **篇幅深度**：精简 / 标准 / 深度（深度 = 整套 70 页以上）。
5. **输出结构**：分册（理论/实战/题本）还是合订；确认地区文件夹名。

## 二、固定交付标准

- 排版：封面 + 目录（带真实页码）+ 分部分/分章节，严谨有逻辑。
- 内容：多维度展开；教师岗附当地学校简介与在用教材版本，非教师岗不附。
- 美化：多种图表（时间轴/雷达图/流程图/思维导图/对比表/环形图），配色统一；**每个项目换一套风格配色**。
- 输出：**每个地区单独建文件夹**，产物为 PDF，单次产物全部放入该文件夹。
- 去痕：无 AI 味、无数据源、无机构名（页脚署名除外）；信息仅来自官网。
- 页脚：极小的整理署名 + "第 X 页 / 共 Y 页"。

## 三、技术管线（本地已验证）

**环境**：`python3`（需已装 playwright + pymupdf，Chromium 随 playwright 一并安装）。
字体：标题 `"Hiragino Sans GB","STHeiti"`，正文 `"Songti SC"`。

**步骤**：
1. 调研考情：WebFetch 官方公告（政府门户/招考网），提取面试形式、时间节点、岗位；WebSearch 区情/时政素材。
2. 建目录：`<工作区>/<地区>/`（产物 PDF）、`_build/<地区>/`（源文件）。
3. 写 `style.css`：A4、`@page{margin:0}`（页边距交给 Playwright）、`-webkit-print-color-adjust:exact`。设计 token 用 CSS 变量，便于换风格。
4. 写 `dX_body.html`（封面**不含**在 body 内）+ 在 `docs.json` 描述封面字段。
5. 用 `scripts/render.py` 渲染：
   - 封面单独渲染成全出血页（margin 0，无页眉页脚）。
   - 正文渲染 A4，`display_header_footer=True`，页脚含署名与页码。
   - PyMuPDF 搜索标题文本 → 回填目录页码 → 二次渲染。
   - 合并封面 + 正文。
6. 校验：页数、页脚署名、目录无未解析项（"00"）。

## 四、关键坑（务必规避）

1. **目录页码误匹配**：目录里的标题文字会被 `search_for` 命中。
   - 解决 A：目录页放一个**白色**（#FFFFFF）小字标记"导航页"，搜索时跳过含该标记的页。
   - 解决 B：图表/思维导图里的标签**不要**与章节标题用完全相同的字符串（如章节叫"综合分析类"，图里写"综合分析"）。
2. **CSS 生成的隐藏文本**：`display:none` 不会进 PDF 文本层，无法被搜索；要"不可见但可搜"用白色文字。
3. **并行 Edit 冲突**：同一文件多个 Edit 并行会互相覆盖 —— 用一次原子 Edit 覆盖整块，或改用 Python 脚本批量替换。
4. **页数不足**：先按目标页数规划分册（深度版约 26/23/22 页），不足时补充"实战演练、专项训练、素材库、答疑"等实质内容，而非放大字号。
5. **封面页眉页脚**：Playwright 的 header/footer 模板对所有页生效，无法只跳过封面 → 封面必须单独渲染再合并。
6. **导航标记位置**：目录可能跨页，白色标记要放在目录**开头与结尾各一个**。
7. **`@page{margin:0}` 会顶掉 Playwright 的 margin 参数**（实测踩坑）：若 `style.css` 写 `@page{size:A4;margin:0}`，正文会**满版出血**（内容从 x=0 开始、宽度等于整页），而 header/footer 模板自带 `padding:0 15mm` 仍有边距 —— 表现为"页眉页脚正常、正文贴边"的诡异错位。**必须让 `render.py` 的 `margin` 参数与 `style.css` 的 `@page` margin 对齐，并以 CSS 为准**（随附 `style.css` 是 `@page{size:A4;margin:18mm 15mm 16mm 15mm}`，对应 `margin={"top":"18mm","bottom":"16mm","left":"15mm","right":"15mm"}`）。**实测：CSS 声明了非零 `@page` margin 时，`margin` 参数会被顶掉** —— 把参数从 17mm 一路改到 30mm，成品正文顶边（19.5mm）、页眉 y（16.5pt）、页脚 y（826.1pt）三个测量值纹丝不动。所以**改版心必须改 CSS**，改 `margin` 参数不生效。
8. **目录 `data-s` 必须等于正文实际渲染出来的文本**：`search_for` 在 PDF 文本层里找不到就会返回 0。最常见翻车是"章节编号只写在目录、正文 h2 里没有"（目录写"四、面试形式与成绩构成"，正文 h2 只有"面试形式与成绩构成"）→ 全部条目回填为 0。两条对策：① `data-s` 直接用正文标题原文；② 目录里的二级条目（同一章内的多个小节）另用**白色锚点**定位 —— 在正文对应位置插 `<span style="color:#fff;font-size:6pt">场次锚一</span>`，`data-s="场次锚一"`，白色文字不进视觉层但可被搜索。
9. **`position:relative` 的提示框必须加 `page-break-inside:avoid`**：`.tip/.warn/.key` 这类带 `::before` 绝对定位徽标的框，一旦被跨页分片，Chrome 会**按整页宽度而非内容宽度**渲染分片，导致横向溢出到页面边缘并压住页脚（表现为文字被右边缘截断 + 与页脚重叠）。修完再跑越界检测确认归零。
10. **渲染后加一道"填充率自动巡检"，比逐页目检快得多**：
    ```python
    foot = [b for b in doc[1].get_text("blocks") if "署名关键字" in b[4]][0]
    B, TOP = foot[1] - 4, 48.0        # 用页脚块 y 反推内容框底边
    for i, p in enumerate(doc):
        ys = [b[3] for b in p.get_text("blocks")
              if b[4].strip() and "署名关键字" not in b[4] and b[1] > 40]
        print(i+1, f"{(max(ys)-TOP)/(B-TOP)*100:.1f}%")   # <10% 即"孤行页"，必须修
    ```
    同时把 `x1 > 页脚右缘` / `y1 > 内容框底` 的块打印出来做越界检测（页眉块 `y0<40` 要排除）。
11. **孤行页的修法优先级**：**内容搬家 > 删内容 > 拉伸留白**。某章结尾溢出 1—3 行、导致下一页几乎空白时，最优解是把上一页有空档的**另一章中的某个小节整段搬过来**（改编号即可，如把"8.4 场外思考怎么用"移为"6.5"）—— 一次同时修好"溢出页"和"偏空页"，且不损失内容。实测一次搬家即从 24 页降到 22 页、消除全部 <10% 页面。

## 七、轻量替代管线（无 Playwright / 单文件 HTML 时用，已实测）

只做"单文件 HTML → PDF + 页脚页码"时，用系统无头浏览器 + PyMuPDF 后处理更省事，**不必拆封面、不必合并**：

1. **渲染**：`chrome-headless-shell --headless --disable-gpu --no-pdf-header-footer --no-sandbox --print-to-pdf=out.pdf "file://<urlencode 后的绝对路径>"`。
   - playwright 缓存路径：`~/Library/Caches/ms-playwright/chromium_headless_shell-*/chrome-headless-shell-mac-arm64/chrome-headless-shell`
   - 备用：`/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge --headless …`
   - 注意：file:// 路径中的空格和中文**必须** urlencode，否则打不开。
2. **回填目录页码**：PyMuPDF 逐页 `get_text()` 定位章节——**用"章节正文首句"当锚点，不要用章节标题**（标题会同时命中目录页，导致误判）。正则替换 TOC 占位符后重渲染。
   - **必须迭代**：改动页脚或分页样式会整体位移，回填后要再跑一轮校验，实测常需 2 次。
3. **加页脚**：PyMuPDF 逐页 `draw_line`（细分隔线）+ `insert_textbox(..., fontname="china-ss")`——`china-ss` 是内置中文黑体，**无需外挂字体文件**。跳过第 0 页即可实现"封面无页脚"。
   - 定位：`y = 页高 − 30pt`，落在 15mm 下边距内，不会压正文；左署名 `align=0`，右页码 `align=2`。
4. **校验**：`page.get_pixmap(dpi=100)` 导出全部页 → PIL 拼 6×5 缩略图，一眼看整体版式与异常空白。

**分页密度（重要）**：把 `page-break-inside:avoid` 加在"题干+答案"整块上，会在页底留下大片空白（实测 30 页里有 5 页空掉近 1/3）。改为只在**题干行**加 `page-break-after:avoid; break-after:avoid`、答案允许跨页，页数可压缩约 8%（30 → 28 页）且观感更紧凑；题干仍不会被单独甩到页底。

## 八、结构化面试真题汇编（题本类）编排惯例

- 结构：**封面 → 考情说明 → 目录 → 按年份分章 → 章内按"招聘单位+日期"分场次 → 附录**（题型答题框架、地区区情速览）。
- 每场次固定 3 道题，按"题目 + 参考答题思路"成对排版；思路统一用「题型 / 破题 / 要点①②③④」四段式，便于速记。
- 真实性标注：**考生回忆**的场次打角标（金色小徽章），同类还原补充的场次不打标，并在目录页用一行"说明"交代区分方式——既专业又不留 AI 痕迹。
- 题目按"招聘单位 + 年月"编排，同一年内按时间先后排序；章内引言一句话点明该年命题风格变化，让汇编有"考情脉络"而非单纯罗列。
