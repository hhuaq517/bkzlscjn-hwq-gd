# 考情手册 PDF 制作

**触发信号**：用户发来一句话，格式基本是 `<地区/单位> + 考情`，例如「交通运输部所属事业单位考情」「佛山市教师校招考情」「南沙区编外人员考情」。
**这就是完整需求**——不要反问"你想让我做什么"，直接按下文澄清四项口径后开工。

**与 `exam-prep-pdf` 的区别**（别用错技能）：
| | 考情手册（本技能） | 备考资料（exam-prep-pdf） |
|---|---|---|
| 目的 | 帮考生**看懂这场考试**、判断值不值得报 | 帮考生**学会怎么考** |
| 内容 | 公告机制、规模趋势、报考条件、竞争比、薪酬 | 知识点、讲义、题本、答题框架 |
| 数据源 | 历年公告 + **岗位表附件逐条统计** | 真题、教材、区情素材 |

## 一、开工前澄清（四个问题，用 AskUserQuestion 一次问完）

这四项在系列项目里**每次都不同**，问错方向整册重做：

1. **覆盖范围**——单区/单单位？还是全市/全省对比？还是"驻本地 + 全国统招对照"双口径？
2. **手册类型**——全流程综合？还是面试专项？还是"两类招聘机制对比"？
3. **时间跨度**——近三年 / 近五年 / 近六年（默认近六年，够画趋势线）
4. **称呼**——用户希望怎么被称呼（记到 `~/.workbuddy-ai/USER.md`）

> 若用户已在 USER.md 里有记录的习惯（称呼、城市、红线），直接沿用，不必再问。
> **若本系列已有同类先例**（如已做过"汕头辅警"再接到"揭阳辅警"），**口径直接沿用先例**，不要重复提问——用户指令短，重复问会烦。只有在"先例不存在"或"新项目明显与先例不同"时才问。

## 二、固定交付规范（系列铁律，不要每次重新确认）

- **目录**：`{工作区}/{市}{区}{项目}考情/`（如 `佛山市教师校招考情汇总/`）。一个地区一个文件夹。
- **文件**：**只交付最终 PDF**。脚本、临时图表、HTML、附件全部放 `/tmp/<项目>_work/`，交付文件夹内**只有 PDF**。
- **篇幅**：精简版 15—25 页。实测 22—25 页是甜点区。
- **版式**：印刷级 A4。封面 + 目录（带真实页码）+ 章节体系 + 附录。
- **图表**：柱状/折线/饼图/环形/雷达/条形**混用**；每册按项目性质换一套配色（见第七节）。
- **落款**：页脚 + 封面 标注"广东中公教研"。
- **红线**（违反即返工）：
  - 除广东中公外**不出现任何机构名**（华图/粉笔/京佳/offcn/huatu/fenbi 等，交付前必 grep）
  - **不展示数据源**、不写"据XX网转载"
  - **公告原文里的报名平台域名要模糊化**：公告正文写的报名网址（`qgsydw.com` / `chinahr.com` / `zhaopin.com` 等）在 PDF 中一律改写为"**以公告原文为准**"或"公告指定网站"（`.gov.cn` 政府门户域名可保留）
  - **无 AI 痕迹**（不写"本文由AI生成""以下内容仅供参考"之类的自我指涉）
  - 非公开数据（竞争比、薪资）可估算，但必须标注"参考/测算"

## 三、十种手册原型（选一个当骨架）

> **先判类型，再动手**。判错了整册框架重做。判据：招聘主体数量（1 个 / 多个）、是否有并行通道、是否分批次、公告是否只覆盖近 1—2 年。
> - 一句话只有"XX公安局辅警" → 先查**市局本级是不是每年招**，是 → 原型 E（批次制）；否 → 再数**空档年与高峰年批次数**：有县区并行 → 原型 E（间歇 + 县区并行双口径）；无县区并行但高峰年一年两批 → 原型 E（间歇 + 单单位多批）
> - 一句话是"XX社区专职 / 社区工作者" → 先查**是不是一年多批 + 有 A/B 双轨岗**，是 → 原型 I（批次滚动型）；否 → 原型 A
> - 一句话是"XX医疗卫生系统 / 医院招聘" → 先数**有几条并行通道**，≥3 条 → 原型 H；只有一条统考 → 原型 A
> - 一句话是"XX基层服务岗 / 基层公共就业创业服务岗位 / 三支一扶 / 双百社工 / 基层项目" → 先查**是不是省级办法统筹、每两年一批、纯笔试无面试**，是 → 原型 K（省级统筹基层服务项目型）
> - 一句话是"XX地区区情 / 适用各类招聘考试"（**没有**具体招考项目）→ 原型 J（区情通用册）

### A. 单区单项目型
`项目概况 → 历年公告参数汇总表 → 招聘规模趋势 → 最新公告解读 → 岗位表分析 → 历年镇街/单位分布对比 → 竞争比 → 笔试考情 → 面试考情 → 薪酬待遇 → 备考建议 → 附录`

### B. 跨区汇总型
`总览 → 两类招聘机制对比 → 规模趋势 → 当年横比 → 报考条件 → 流程时间 → 笔试 → 面试 → 成绩合成 → 竞争比 → 薪酬 → 综合画像(雷达) → 分区点评 → 备考策略 → 时间表渠道 → 结语`

### C. 面试专项型
`编制说明 → 制度底色 → 招聘通道对比 → 招聘全景与规模 → 面试形式与成绩构成 → 进面比例双轨 → 全流程拆解 → 测评要素体系 → 命题风格 → 题型示例 → 区情素材库 → 答题框架 → 逆袭测算 → 备考节奏 → 附录`
> 差异化抓手：进面比例双轨（1:3 vs 1:5）、多套公告测评要素表述、逆袭分差测算。
> **实操要点（阳东区合同制职员册验证）**：
> - 面试考情的**第一手素材在"面试公告"里，不在招聘公告里**。面试公告写明面试方式（结构化）、**每人几题几分钟**、报到与抽签时间、候考纪律、候分流程。检索式：`<地区> <项目> 面试公告`，逐批次抓，就能拼出"题量/时长演变"这条最有价值的线索（如 2 题 10 分 → 3 题 15 分）。
> - 进面比例的差异往往来自**招聘主体不同**（机关事业单位 1:3 / 区属国企 1:5），不是年份变化，要按通道分轨讲。
> - "**放弃资格审核不递补、不合格才递补**"这类程序细节是考生最容易吃亏的点，单列一个提示框。
> - 编外/合同制类常无公开真题 → 用**同区域同命题体系**的事业编/选调真题作"命题风格参考"，在编制说明与正文**双重标注**并提示"题目不重复"。

**变体 C-2：市直统招面试专项型**（市级教育局统一招聘的教师岗，2026-09 实测 25 页）
`编制说明+目录 → 一 制度底色（招聘主体/统一分配/服务年限） → 二 招聘全景（批次参数总表） → 三 规模与门槛演变 → 四 最新批次深度解读 → 五 最新批次三处关键变化 → 六 面试形式全解 → 七 成绩构成与合格线演变 → 八 进面规则与实测进面比 → 九 全流程拆解 → 十 面试现场（候考/抽签/纪律） → 十一 测评要素与评分维度 → 十二 试讲命题范围与学科特点 → 十三 答辩题型与应答框架 → 十四 面试成绩全景 → 十五 各学科面试分线与拟聘门槛 → 十六 逆袭测算 → 十七 竞争态势与招录完成率 → 十八 本地区教育背景素材库 → 十九 薪酬待遇与职业发展 → 二十 备考节奏与时间表 → 附录 A 历年批次参数 / B 最新批次职位表全文 / C 数据口径`
判据：**市级教育局统一发布公告、统一考试、统一分配岗位**，岗位表按学科分设，且历年批次密集（珠海 6 年 9 批）。
与原型 C 的三点差异：
1. **"面试合格线"与"成绩权重"要各设一章并做成演变图**——这两条是教师统招最强抓手（珠海：合格线 80→60→70 三档跳变；权重 50:50→40:60）。
2. **"各学科面试分线"必单列**——用「拟聘最低面试分」与「全体面试最低分」之差算「逆袭空间」（珠海高中数学 18 分空间 vs 高中政治 7 分），比单纯报名人数更有参考价值。
3. **答辩/试讲是"归纳型"章节**，公告不公布题库 → 必须写明"按面试形式与学科特点归纳的备考方向，非真题"，并给出各学科教材范围与命题侧重表。
**该型最强抓手**：① **公告口径 ≠ 实操口径**（珠海 2025 秋招聘公告写"试讲＋答辩"，实操公告只有"试讲（技能测试）"）——必须对照招聘公告与面试工作公告两份文件；② **公示周期**（珠海 2025 秋 12 月面试 → 次年 4 月首批公示 3 人 → 8 月第六批 39 人，跨度 9 个月）；③ **合格线上调的量化测算**（用上一批次成绩分布模拟新线下的淘汰人数）。

### D. 部委直属事业单位型
`制度底色(统一招聘机制考证) → 招聘全景与规模(按年度×批次) → 驻粤单位专题 → 报考条件 → 全流程 → 笔试考情 → 面试考情(多套规则对比) → 薪酬 → 备考策略 → 附录`
> 关键：这类单位的"年度"**不是自然年**，起点在上一年 9—11 月；且多为**按批次滚动招聘**（一年 7—9 批），不是一年一考。必须先把这个机制考证清楚，否则整册框架错。

### E. 公安警务辅助人员型（辅警 / 公安机关非编制岗）
`编制说明 → 目录 → 一 项目概况与制度底色（辅警身份定位 + 招聘机制） → 二 招聘全景（历年批次参数汇总 + 规模趋势） → 三 最新年度公告深度解读（参数对照 + 三大政策变化） → 四 岗位体系演变 → 五 岗位一览与选岗策略 → 六 报考条件详解 → 七 全流程拆解（十二环节时间轴） → 八 体能测评 → 九 笔试考情 → 十 面试考情 → 十一 薪酬待遇与职业发展 → 十二 备考策略 → 附录 A 历年公告参数 / B 岗位表全文 / C 数据口径`

**目录命名**：`{市}{公安局}警务辅助人员招聘考情`（不带"分局"或"区"，以市局本级为准）

**四条结构变体**（开题时必须判断属于哪条）：
- **批次制型**（汕头）：市局本级连续多年招，每年 1—3 批 → 主线清晰，直接按批次排
- **间歇 + 县区并行型**（揭阳）：市局本级**不是每年招**（揭阳 2022/2023/2024 三年零公告），补员压在县区分局 → 必须**双口径**：市局本级为主线 + 全市县区格局单独一章（含"分局招录对照表 + 堆叠柱状图"）
- **间歇 + 单单位多批型**（珠海拱北口岸，2026-09 实测）：**同一个单位**不是每年招，但高峰年一年两批（珠海 2021—2026 共 8 批 / 270 人，**2024 整年空档**，2022 双 70 人、2026 双 28 人），**无县区并行** → 不需要"县区格局"章，改为「岗位体系演变 + 各用人单位投放版图」两章，把岗位表**逐条归集到派出所/大队**（哪个单位是持续补员点、哪个是偶发）。判据：先数**空档年**，再数**高峰年的批次数**
- **一年多批 · 市局本级主导型**（珠海市公安局本级，2026-09 实测，24 页）：市局本级**几乎每年都招且一年多批**（2025 年投 2 月/5 月/8 月三批），分局仅作零星补充（香洲、高新、拱北口岸各自发公告）→ 主线按批次排，另设「全市投放版图」一章讲各主体规则差异。判据：市局本级批次数 ≥5 且覆盖 4 年以上 → 归此类，不要按"县区并行型"处理。**最强抓手**：市局本级与下属单位的**口径并轨时点**（珠海市局本级 2023.06 就改 40:60，拱北口岸拖到 2026.09 才跟，香洲分局 2026.07 已跟）

- **年度统招元年型**（广州市公安局本级，2026-09 实测，24 页）：市局本级**在某一年首次建立"年度统一公开招聘"机制**，把原先分散在警种/分局的零星补员上收为一年两次统招 → 判据：**招聘主体从"警种/分局"上收为"市局本级"**、同年出现两次统一招聘、单批规模跳升（广州 2025 单批均值 80 人 → 2026 均值 583 人）、岗位表从"按单位列"改为"按工作性质/专业分类列"。**主线写法**：不要按"批次"平铺（那样前几年全是碎批），改为「**机制换挡**」叙事——① 制度底色讲身份与勤务形态；② 招聘全景按"年度投放 + 单批体量"双柱图讲**陡坡**（广州 2021—2026 投放 430/232/65/217/401/1165，2026 一年＝前五年总和 87%）；③ 最新公告深度解读四通道逐条对照；④ 两次招聘参数对比表（同一年内两次对照，是最强抓手）；⑤ 岗位结构画像。**判据补充**：若"最大批次的年份＝最新年份"且规模是历史均值 3 倍以上 → 归此类

**该单位不公示拟聘名单时怎么办**：珠海拱北口岸不公开入围/拟聘名单，强抓手 2、3 失效 → 改用「**批次规模变化 + 岗位结构迁移 + 用人单位投放频次**」三条线做规律归纳，全部标注"测算"。不要因为拿不到名单就跳过竞争强度章节。

**拟聘名单里"生源地画像"是可复用的强抓手**（广州册实测）：拟聘公示常含身份证号前六位 → 行政区划码归集出**生源地结构**（广州 2025 交通辅警 150 人：广东籍 78.0%、广州籍 42.7%）。更妙的是**拿补录批次做对照**（广州 2026.2 补录 31 人：广东籍升到 90.3%、广州籍 58.1%）→ 得出"**递补阶段本地考生报到意愿更强、放弃率更低**"这条洞察。这是"名单类"数据除了竞争比之外的第二个用法，凡名单带身份证号的册子都要做。

**强抓手（按优先级）**：
1. **"今天发的最新公告"为核心解读对象**——撞上开题日就 100% 做深度解读（参数对照表 + 逐条岗位分析 + 三大政策变化），这是手册最硬的差异化卖点
2. **招录完成率**：用"计划数 vs 拟聘数"当"招人热度"指标（如揭阳 2025 招 154 / 拟聘 137 = 88.96%）
3. **入围名单是金矿**：含"准考证编号—报考岗位—姓名—性别"，**编号最大值 ÷ 招录计划 = 竞争强度指数**（辅警不公布报名人数，这是唯一公开代理指标，口径必须标"测算值"，不能等同报录比）
4. **体能项目演变**：如 1000米/800米跑 → 10米×4 往返跑；纵跳 255→265 cm。这是"门槛变化"的最直观信号
5. **成绩合成双轨**：达标制（面试不计入总成绩，总成绩=笔试）vs 合成制（笔试×60%+面试×40%）——**同城内不同招聘主体可能用不同规则**（揭阳：市局/揭东达标制，惠来 2026 首次合成制），这是最强的差异化抓手
6. **同城内"市—县"标准不同步**：揭东 2023 就用 10米×4，市局本级 2026 才跟进；2026 市局 ≤13″1/纵跳 265、揭东 ≤14″1/纵跳 255。这种"同城不同标"是很好的洞察素材
7. **权重反转 / 口径换代是顶级抓手**：珠海拱北口岸 2021—2026.03 六个批次恒为笔试 50%＋面试 50%，**2026.09 首次改为 40%:60%**（逆袭系数 1.00→1.50）；同城香洲分局 2026.07 同步 → 用"**全市同步**"证明是口径调整而非个体行为。同类信号：长跑→平板支撑、高中以上→大专及以上、邮箱投递→网络报名系统、五板块笔试→三板块
8. **薪酬口径换代必须点明"不可横比"**：珠海三个批次分别是"年薪 5 万（学历分档）""人力成本 7.07 万（含装备费培训费）""薪酬 6.4 万（含五险一金）"——数字有升有降，但**是口径变了不是待遇变了**，直接横比会误导考生

**数据获取要点**：
- 官网通常分两栏（如汕头 `zwgk/gggs/` + `zwgk/ryzl/`；揭阳 `jyga/gggs/` + `jyga/xxgk/rsxx/`）——**两栏都要翻**，只用一栏会漏历年
- 官网栏目**往往只保留近 1—2 年**，更早的公告已下架 → 靠转载站补齐（**不展示来源**）

  - **广州市公安局官网**（`gaj.gz.gov.cn`）：栏目 `zwdt/tzgg/`（通知公告，翻 50 页 971 条）＋ `xxgk/`。**实测只保留近两年（2025—2026）**，2021—2025 的历年批次必须靠公开转载页补齐（本次靠搜索凑齐 2021—2025 共 16 个批次）。附件直链 `gaj.gz.gov.cn/attachment/0|7/{目录}/{文件}/{post_id}.{ext}`，带 `Referer` 可下。公告页偶发"搜索引擎有、直接访问 404"（见第七节工程类第 20 条）→ 改走转载页拿正文与附件直链

- 体能标准常是公告正文里的**图片**（PNG 200—300 px 宽）→ 需视觉识别读取数值
- 岗位表附件格式不定：`.pdf`（pypdf）/`.xls`（xlrd）/`.docx`（zipfile 提 `word/document.xml`）都遇到过，逐个试

### K. 省级统筹高校毕业生基层服务项目型（2026-09 新增）
`编制说明+看点+目录 → 一 制度底色（省级办法 + 周期机制 + 岗位性质 + 同类项目对比） → 二 招聘全景（按周期参数总表 + 规模趋势 + 名额分配演变 + 招录完成度） → 三 最新年度公告深度解读（参数速览 + 变化点逐条） → 四 双轨报名机制（困难生优先） → 五 岗位表与选岗策略 → 六 报考条件逐条 → 七 全流程时间轴 → 八 笔试考情 → 九 竞争态势与分数线 → 十 录取画像 → 十一 薪酬与职业发展 → 十二 备考策略 → 附录 A/B/C`

**目录命名**：`{市}基层公共就业创业服务岗位考情`（或按用户口径简称 `{市}基层服务岗考情`）

**核心区别：投放按"两年一批"的省级周期，不按年度；且报名是双轨制。** 判据三条同时成立即归此类：

3. **纯笔试无面试**（近年形态）：只考《行政职业能力测验》一科，全市统一命题制卷，合格线 60 分，**总成绩即笔试成绩，不存在面试逆袭**。注意查历年演变——早期可能是"排序招聘"（困难生人数≤岗位数则免笔试），中间年份补录可能加试面试。

**强抓手（按优先级）**：
1. **困难生优先的"占满效应"**（本类册最强的差异化素材）：某岗位困难生报名人数超过岗位数时，**剩余名额为零，普通考生会集体缺考**。汕头 2022 年度澄海区 8 个岗位被 16 名困难生锁定 → 22 名非困难考生全部缺考 → 该岗位进体检线仅 56.3 分（低于 60 分合格线，因困难生内部竞争不设线）。**这类"还没考就结束"的案例，是普通考生最需要提前知道的**。
2. **同分规则的罕见度**：部分地市规定"按试卷第一道题得分高低排序，第一题相同比第二题，以此类推"——**题目顺序直接参与排名判定**，不能用"放弃常识题"的常规策略。查公告时务必逐字读成绩规则。
3. **两年一批的时间规律**：三个周期公告发布日往往全部落在同一个月份（汕头均为 9 月）→ 该月无公告即当年不招，可写进册子作为硬提示。
4. **名额分配的高度稳定性**：多数区县岗位数跨周期完全不变，增量只落在个别中心城区（汕头仅金平、龙湖在扩）→ 说明岗位供给已进入稳态，扩容由省级指标而非地方意愿决定。
5. **省级办法里的制度上限**：如"市本级指标原则上不得超过 2 个"，直接解释了市直岗位为何常年只有 2—3 个。
6. **待遇的"减法"必须点明**：公告常写"服务期间不再叠加享受 XX 地区就业补贴政策"——这是机会成本，做待遇测算时要计入。

**数据获取要点**：
- 岗位表附件常见 `.wps`（OLE2，macOS 用 `textutil -convert txt` 可转）与 `.et`（WPS 表格，xlrd 可直接读）
- **拟聘公示名单的准考证号是估算报名规模的金矿**（公告不公布报名人数）：先看前几位是否统一、后几位是否为"考场号+座位号"。汕头 2024 年度为 `8804010 + 考场号(2) + 座位号(2)`，考场 01—14 连续、座位号最大 30 → 报名上限约 420 人。**必须标"测算"**。
- **公示往往是分批的**（汕头 2024 年度分了 4 批 + 2 次补录），分批统计后加总，并与计划数核对是否吻合——吻合即验证了"招录完成率 100%"
- 成绩表附件若含考生级明细（姓名/岗位/困难生标记/分数/是否进体检），是**最高价值的数据源**：可同时算出竞争强度、分数线、缺考率、困难生占比、性别结构
- 口径校验：`记录数 − 缺考数 − 免笔试困难生数 = 参加笔试人数`，与公告正文数字对得上才算解析正确

### L. 系列册批量生产型（一次多册，2026-09 实测，九册×15 页）

**触发**：用户一次丢来 N 张**同系列单页图**（考情地图 / 信息图），要求「每张图每个地区为单位，每个地区整理一份考情分析，用当前的图作为首页图，其他的内容配合首页内容，配色搭配」。

**交付**：N 个文件夹，每个文件夹内**只有 1 个 PDF**。每册 15—17 页。

**骨架**（每册同构，只换数据）：
`封面（原图满宽） → 编制说明+本册看点+阅读指引+目录 → 一 全市招录总览（6 格数据卡+投放结构环形图） → 二 区县招录版图（规模条形图） → 三 招录节奏（公告时间轴点阵图） → 四 区县逐区拆解（卡片） → 五 笔试科目体系（表+优先级） → 六 面试形式谱系（表+要点） → 七 报考门槛与通道 ＋ 八 赴外考点与专场机制（**两章合一页**） → 九 薪酬待遇（九市薪酬区间图） → 十 珠三角九市横向坐标（九市规模图） → 十一 竞争态势与报考策略（对照表+动作清单） → 十二 备考节奏 ＋ 十三 结语（**两章合一页**） → 附录 A/B/C → 封底（系列一览表+编制信息）`

**六条关键工程做法（照做即可，别重新发明）**：

1. **原图直接当封面**：图满宽 `210mm`，高度按图比例算（1080×1440 的 3:4 图 → `280mm`），**余下正好 17mm** 放主色署名带（左：册名；右：广东中公教研）→ 280+17=297mm 精确满版，不要缩放、不要留白边。
2. **配色从原图里提，不要凭感觉选**：`PIL` 读图 → HSV 过滤 `s>0.55 且 v>0.4` → 按 8° 色相分桶统计 → 取前几名当主色。中公系考情地图实测恒定得到：主红 `#B4232F`、琥珀金 `#B98A2E`、中蓝 `#2C6C93`、深藏青 `#1F3350`、浅底 `#EDF2F7`。**同系列九册共用一套色**，读者一眼认出是一个系列。
3. **数据底稿 + 并行研究员两段式**：
   - 先由主理人把每张图的文字**逐条转录**成 `base.py`（每市一个 dict：`total / top / units[(名称,人数,公告,笔试,面试,口径)] / pending / salary`），**这一步不外包**，是全书可信度的地基。
   - 再写一份 `SCHEMA.md`（章节键名、每字段字数区间、各章必写内容、红线、**并把第六·五节"去 AI 味自检清单"整张表贴进去**），**并行派 N 个子代理**，每人只写自己那一个 `<key>.json`，写完自行 `json.load` 验证。
   - 收回后跑一次统一校验脚本（键名齐全 / 字数区间 / 红线正则 / ASCII 引号 / Markdown 残留）。实测九份一次过，只有一处 `highlights` 条数超标（渲染端兼容 4—5 条即可，不要回炉）。
4. **一个生成器出 N 册**：`build.py` 读 `base.py` + `<key>.json` + `charts/<key>/*.svg`，循环输出 N 个 `index.html`。**页序在 Python 里先算好再写死**（`plan = {...}`，目录页码直接取 `plan` 的值），不依赖 JS 回填 → 目录页码**构造即正确**，不需要事后核对。渲染完仍要用脚本复核一遍（`pn = PDF 索引`，封面不编号）。
5. **卡片页自适应密度**：单位数 ≥11 时给卡片容器加 `.dense`（缩字号 8.1→7.7pt、行高 1.56→1.5、gap 2.8→2.2mm、padding 2.2→1.8mm）压到**一页**。实测深圳 11 张卡：拆两页填充率 61%/53%，压成一页 **94%** —— 密集但可读，观感反而更像专业册子。
6. **无人数口径的城市，条形图必须退化**：按「片区 / 组团」组织的城市（东莞、中山）单位人数为 0，`barh` 只剩一根柱子，在 `bbox_inches='tight'` 下会渲染成一个**巨大的色块**（中山实测）。改为**「本市首期专场占九市合计比例」环形图**（142/9100=1.6%），既填页又正好把「量小」讲清楚。

**其他批量坑**：
- 单册 15 页是这套骨架的自然结果，不要为凑 22 页灌水；九册一次交付时 15—17 页/册是合理区间。
- 「两章合一页」在目录里**允许两行同页码**（如第七章、第八章都写第 8 页），比把短章各占一页（35%—42% 填充率）干净得多。
- 子代理写的 `lead` 里若声称「按规模从大到小」，渲染端**必须真的按人数降序排卡片**，否则图文不符（深圳实测踩到）。排序键：`(是否暂未发布, -人数)`，稳定排序可保证无人数城市保持原顺序。
- 九册合一的横比章（「珠三角九市横向坐标」）要用**全部九张图的数据**，这是系列册独有的差异化素材；把 `NINE` 常量放在 `base.py` 里供九册共用。

## 四、数据获取管线（本技能的核心价值）

**考情手册的可信度 = 岗位表附件的逐条统计**。不要用转载的二手数字。

### 1. 抓公告页 → 提附件链接
```python

```

### 2. 下载附件（两个必踩的坑）
- URL 含中文/空格 → 必须 `urllib.parse.quote()` 逐段编码
- 多数政务站点要带 Referer 才给下载 → `headers={'Referer': 公告页URL}`

### 3. 批量解析岗位表 → 见 `scripts/parse_positions.py`
要点：
- `.xls` 用 `xlrd`，`.xlsx` 用 `openpyxl`，两者 API 不同，用 `read_sheets()` 统一成 `[(sheet_name, rows)]`
- **表头行位置不固定** → 动态定位：找同时含「岗位编码」和「招聘人数」的行
- **合并单元格"控制数 N 人"** → 人数列常写成"控制数 5 人"或直接空白（合并单元格）→ `to_int()` 用 `re.search(r'(\d+)', s)` 抓任意位置数字，并记录 `ANOM` 异常
- **考试形式在表头上方的合并单元格里** → 必须 `cells = [str(x) for x in r if x]` → `' '.join(cells)` 再判断，只匹配单个标签单元格会漏
- 解析完**必须与公告正文的人数交叉核对**（对不上就是解析错了，别硬写）

### 3.5 区情素材（面试专项册必备）
政府门户站的"魅力XX / XX概况"栏目是**权威且安全**的区情来源（下辖镇、面积、海岸线、产业名片、土特产、文旅资源）。抓一次即可复用到多册，避免用百科二手数据。检索式：`<区名> 概况 site:gov.cn`，或直接抓门户站栏目页。

### 3.6 历年公告补齐（必做，别只抓官网）
**官网栏目通常只保留近 1—2 年**（实测：揭阳公安 `gggs` 栏目仅 60 条覆盖 2025—2026，汕头 `ryzl` 也只到 2024）。补齐路径：
1. 先翻官网**所有相关栏目**（不止一个——`gggs` 公告公示 / `rsxx` 人事信息 / `ryzl` 人员招录，各栏目的收录范围不同）
2. 官网缺失的年份，用**转载站补齐**（检索式：`"<单位全称>" "<年份>" 招聘公告`）；**不展示来源**
3. 若公告原文已 404，但转载页保留了**全文与附件链接**，可从转载页提取数据（同样不展示来源）
4. 关键附件（岗位表 / 体能标准 / 拟聘名单）**必须下载原件解析**，不要用转载页的表格截图

### 3.7 附件格式不确定时逐个试
同一单位的历年附件格式可能年年不同（实测同一市局：2026 岗位表 `.pdf`、2025 岗位表 `.docx`、专业目录 `.xls`）：

## 六、质检清单（交付前逐项跑）

### 1. 溢出检测——JS 注入法（比像素法准得多）
注入到 `check.html` 末尾：
```js
window.addEventListener('load', () => {
  const MM = 96 / 25.4;          // 1mm = 96/25.4 px
  const PAD_BOTTOM = 12;         // 必须与 CSS .page 的下内边距一致（mm）
  const bad = [];
  document.querySelectorAll('.page').forEach((p, i) => {
    if (p.classList.contains('cover')) return;   // 封面是装饰性全出血页，装饰圆故意超出，必须跳过
    const c = p.querySelector('.content');
    if (!c) return;                              // 无 .content 的页不参与判定
    const limit = p.getBoundingClientRect().bottom - PAD_BOTTOM * MM;  // 内容允许到达的底线
    let maxB = c.getBoundingClientRect().bottom;
    // 连子元素一起取 max：.content 若被 CSS 定了高，内部溢出仍能被抓到
    [...c.children].forEach(el => {
      const b = el.getBoundingClientRect().bottom;
      if (b > maxB) maxB = b;
    });
    const ovf = Math.round(maxB - limit);
    if (ovf > 2) bad.push((i + 1) + ':' + ovf);
  });
  document.title = 'OVFCHK::' + (bad.length ? bad.join('|') : 'none');
});
```
取出：`Edge --headless=new --dump-dom file://.../check.html | grep -o 'OVFCHK::[^<]*'`
**目标：`OVFCHK::none`**。有数值就按第七节修，改完重跑。

> 🚨 **绝对不要用 `c.scrollHeight - c.clientHeight`**。本系列的 `.content` 是 `height:auto`（靠内容撑开），此时 `scrollHeight === clientHeight` **恒成立**，结果永远是 0 —— 任何溢出都测不出来，一律返回 `OVFCHK::none` **假通过**。东莞教师册第一轮就因此漏掉了 P12 的 7px 溢出，直到目检才发现。**必须用 `getBoundingClientRect` 对比真实几何底边**（上面写法）。同理 `.content` 没有固定高度时，"给 .content 设 overflow 后比 scrollHeight"这类变体也一律无效。
>
> `PAD_BOTTOM` 必须与 CSS 里 `.page` 的下内边距对齐（本系列默认 12mm）。改成别的值会让底线整体偏移，产生成片假报警或成片漏报。

> ⚠️ **封面必须排除**：用 `p.querySelector('.content') || p` 这种兜底写法，会把封面的装饰圆/色块（`overflow:hidden` 已裁掉的部分）算成溢出，中广核册实测**误报 `1:272`**。凡是"全出血装饰页"都不能参与溢出判定。

> 📌 **脚本版**：`scripts/overflow_check.py` 已内置上述正确写法，可直接跑：
> `python scripts/overflow_check.py build/index.html --pad-bottom 12`

### 2. 填充率巡检（找孤行页）
统计每页内容最低非白行占 A4 高度的比例。
**目标：全部 > 55%，无 < 10% 页面。**
**正确算法**（实测两次踩错）：
```python
im = np.array(Image.open(png).convert("L"))
rows = (im[:792] < 235).any(axis=1)      # 只扫 0—792pt（内容框底），把页脚排除在外
fill = (rows.nonzero()[0].max()) / 842   # 842 = A4 高
```
- ❌ 用页脚线位置当内容底 → 全页误读 0%
- ❌ 用 `im.min(axis=1)` → 语义错，同样读出 0%
- ✅ 固定 **792pt** 为内容框底（页脚在 792 之下），阈值 235 判非白
南网册实测 71.2%—98.7%，其中 98.7% 经目检为"图表下沿距页脚尚余约 8mm"，可接受——**填充率高不等于溢出，仍须目检**。

### 3. 合规 grep（四查）
```bash
pdftotext out.pdf - | grep -c -E '华图|粉笔|京佳|offcn|huatu|fenbi|上岸鸭|本地宝'   # 必须 0
pdftotext out.pdf - | grep -o '中公' | wc -l                          # 应等于页数+封面（全部是署名）
pdftotext out.pdf - | grep -c -E 'AI生成|人工智能生成|仅供参考'          # 必须 0

```
> 第 4 条别漏：公告原文抄来的报名网址（`qgsydw.com` 等）会混进 PDF，属"展示数据源"违规。

> **macOS 环境无 `pdftotext`**（未装 poppler）→ 上述四条改用 `pypdfium2` 抽文本再跑同样的正则：
> ```python
> txt = "".join(d[i].get_textpage().get_text_range() for i in range(len(d)))
> ```
> **命中"人工智能"要人工看上下文**：南网册信息通信岗专业名含"人工智能"，属正常业务词，不是 AI 痕迹。同理"AI"、"智能"等词都可能是岗位名。

### 4. 结构校验


写完正文先跑一遍下面的正则体检，命中就改。中文的 AI 味信号和英文不一样，按中文的抓。

### 1. 必查清单（正则 → 处理）
| 信号 | 正则 | 处理 |
|---|---|---|
| 意义拔高 | `彰显｜标志着｜的缩影｜见证｜铸就｜诠释了｜奠定了｜谱写了` | 删掉整句，只留事实 |
| 权威虚指 | `业内人士｜有专家认为｜众所周知｜据分析` | 删，或换成具体主体（如"公告原文写明"） |
| 空洞分析 | `从而(为｜让)｜进一步(提升｜增强)｜有效地｜更好地` | 删 |
| 促销语言 | `不容错过｜性价比之王｜首选之地｜最佳选择｜重磅｜必选｜黄金期｜风口` | 换成中性表述（"第一档""排在前列"） |
| 挑战展望段 | `面临诸多挑战｜未来可期｜前景广阔｜值得期待｜任重道远` | 删掉整段，换具体数据 |
| AI 高频词 | `赋能｜闭环｜抓手｜生态｜纵深｜深耕｜聚焦｜着力｜夯实｜驱动｜引领｜护航｜筑牢` | 换成大白话（"抓手"→"关键"；"聚焦"→"主要讲"；"格局"→"分布"） |
| 系词回避 | `堪称｜不失为｜可谓｜乃是` | 直接写"是" |
| 负向平行 | `不是…而是｜并非…而是｜而非｜不仅…更是` | 拆成两句陈述 |
| 对话残留 | `希望本｜如需｜欢迎咨询｜下面我们来看｜以上就是` | 删 |
| 知识截止免责 | `截至目前公开资料｜据现有信息显示｜在可查证的` | 删，直接写结论 |
| 冗词 | `值得注意的是｜需要指出的是｜不难发现｜由于…的原因` | 删，直接说 |
| 过度模糊 | `或许可能｜在某种程度上｜或多或少｜一定程度上` | 删 |
| 空洞正向结论 | `未来将更加｜大有可为｜充满希望｜迈上新台阶` | 换成具体的下一步动作 |
| 破折号滥用 | `——` | **正文里保留（中文合法用法），但列表模板里必须清零**（见第 2 条） |
| 三连排比 | `A、B、C、和/与/及` 连续出现 | 拆成两项或四项，别凑三项 |
| 加粗滥用 | 每段都有 `<b>` | 每页最多 2—3 处，只标真正要记的数字与结论 |

### 2. 最大的坑：**机械句式是从生成器模板里来的，不是写作方带来的**
系列册实测：九册共命中 81 处破折号，其中 **72 处（89%）来自生成器里的一行列表模板**——
`f'<b>{mark}：{row[0]}</b>——覆盖 {row[1]}，{row[2]}'`。
每个写作方都写得很干净，但这一行模板在九册 × 8 条列表里重复了 72 次，**整册读下来就是扑面而来的机械感**，而写作方完全无从察觉。
**教训：交付前不只查"写作方写的字"，还要查"生成器拼的句子"。** 模板句一律避免"破折号 + 覆盖 + 补充说明"这种固定三段式，改成
`第一优先：教综＋行测（覆盖 宝安 B/C 类、大鹏）—— 时政是新增变量` 这类**变体**，或者干脆把补充说明放进表格第三列，列表只留结论。

### 3. 中文特有的"去味"手法
- **长短句要打散**：连续三句都 40 字以上，读起来就假。插一两句 10 字以内的短句下判断（"这批不值得等。""窗口只有十天。"）。
- **允许不确定**：考情册最像人写的地方，是敢说"这个口径公告没写清楚，只能等"。全篇都给确定答案反而可疑。
- **给动作，不给形容词**：把"竞争激烈"换成"报名基数会同步放大"；把"性价比高"换成"月供能覆盖一半"。
- **别每章都收口金句**：`kicker` 只在真有判断的章节写，凑数的金句比没有更假。

## 七、关键坑（全部实测踩过）

### 排版类
1. **SVG 按容器宽度等比缩放** → 高宽比大的图（雷达图）会溢出页面。用 `max-width` 或压扁 `figsize` 控制实际高度。「表格 + 2 张图」极易超版心，图表宽度压到 **76%—86%**。
2. **A4 单页正文安全容量约 250mm 内容高**。内容不足 70% 时优先**补数据表**而非拉伸留白。
3. **表格列宽过窄会让整表行高翻倍**（最隐蔽的坑）：某列 width 设 8% 时"2027 一批"被折成两行 → 27 行全部变双行高 → 溢出 824mm。**宁可删掉低价值列，也不要给窄列**。
4. **附录长表（>15 行）必须拆两页**，且两页行数大致均衡（如 11 行 + 11 行）。
5. **页脚页码不可用独立绝对定位**（会与右侧署名重叠，导致 PDF 文本抽取串字）→ 用 flex 三栏：标题 / 页码 / 署名。
6. **`.note` / 提示框必须加 `page-break-inside:avoid`**，否则跨页分片按整页宽度渲染 → 横向溢出压页脚。
7. **"编制说明 + 目录"同页时，目录末尾会被静默裁掉**（实测：17 项目录 + 3 个说明框，最后 2 行被 `overflow:hidden` 吃掉，不看目录尾根本发现不了）。修法：`.toc li` padding 收到 `1.45mm`、`.note-s` margin-bottom 收到 `3.1mm` 且 font-size `8.5pt`、`.toc-h` margin-bottom `3.4mm`。**目录页必须一并纳入溢出检测，不要默认它安全。**
   > **目录 ≥20 项时的首选解法：改双栏** `.toc ul{columns:2; column-gap:9mm}`。南沙社区册 24 项目录 + 编制说明同页，双栏一次把填充率从溢出（1105/1022）降到 86.8%，且腾出的空间正好补一张"本册五大看点"表。
8. **目录页码用 JS 自动回填最稳**：`.page` 按顺序写 `data-pn`（封面/封底留空），目录项写 `data-target="章节id"`，加载后执行
   `el.textContent = document.getElementById(el.dataset.target).closest('.page').dataset.pn`
   比按渲染文本匹配更稳，改版不会失效。取回校验：`pdfium` 抽目录页文本核对数字。
   > **例外**：Edge 无头 `--print-to-pdf` 对 JS 执行时机不稳（农发行册实测出现空白页码）→ 若发现 JS 回填失效，**退回手工写死 `data-pn="N"` + 内嵌页码**，不依赖 JS。
9. **每章单独一页、章内小节可跨页**是 23 页规模下最省心的切分粒度；若某页留白 >25%，优先在该章补一节"取材方向 / 趋势判断"类小表，而不是拉伸间距。
10. **`col2` 双栏放长文本会互相挤压**（揭阳册 P04 实测）：双栏各 50% 宽度，长段落被压得很难读 → **改单栏 `<p>` 反而更清爽**。双栏只适合短条目（≤3 行）。
11. **正文里的提示框优先用 `<p><b>标题：</b>正文</p>` 而非 `.note/.warn` 容器**：同样的内容容器会多占 4—6mm 高度，且更容易被页脚切割。页面接近满版时，把末尾提示框降级为普通段落是有效的省空间手段。
12. **末页"编制信息"表里的"页数"字段必须最后回填**：初版按预估写（如写 22 页），实际渲染 19 页 → 交付前必须核对真实页数再填。
13. **分拆章节后有三件事必须同步，漏一个就出 bug**：① **后续所有 `page(N, ...)` 的 `pn` 全部改号**（南网册拆分第十九章时新页沿用旧 pn，导致 P21/P22 都印"20"）；② **小节编号**（原 20.1/21.1/22.1 要顺延为 21.x/22.x/23.x）；③ **目录页码**。改完必须跑一次"页码异常 / 小节编号异常"校验脚本。
14. **页码回填：小册子（≤30 页）手工核对比 JS 回填更稳**。JS 回填只在长册（>40 页、页码易错位）才值得，Edge 无头对 JS 时机不稳，反而引入不确定性。手工核对成本极低：抽目录页文本 + 抽各章首页文本对一遍即可。

### 图表类
1. **多序列折线在收敛区间打点标注必重叠**（如 90/113/133）→ 改用分组柱状图（标签旋转 90°）或**只标注峰值 + 配数据表**。
2. **饼图小切片（<8%）外置标签必重叠** → 改用「环形图 + 右侧独立图例轴」布局。
3. **柱状图的 `ax.legend` 是重叠与溢出的头号来源**（揭阳册反复踩）：图例与标题、与 x 轴双行标签反复打架；`bbox_to_anchor` 放上方 `(0.5, 1.22)` 或下方 `(0.5, -0.28)` 在 SVG 导出中**都不稳定**。
   → **最稳的解法是删图例**：双色柱自明（NAVY/ORANGE），数值直接用 `ax.text` 标在柱顶。确需图例时，改用**右侧独立图例轴** `bbox_to_anchor=(1.02, 0.5)`。
4. **一页放「表格 + 图 + 图 + 提示框」必溢出**（揭阳册 P14 实测）：修法是**删掉冗余图**而非压缩尺寸——若表格已承载同一信息，那张图就是冗余的。
5. **`pie()` 不设 `autopct` 时只返回 2 个值**（patches, texts）；写 `w, t, at = ax.pie(...)` 三 unpack 必抛 ValueError。环形图（`wedgeprops=width=0.36`）尤其注意。
6. **堆叠柱状图 `ax.bar` 循环里不要用 `years.index(b.get_x())` 反查索引**（浮点坐标不在列表里，必抛 `ValueError`）→ 用 `enumerate(bars)` 直接拿序号。
7. **`matplotlib` 中文告警 `Failed to find font weight normal for Hiragino Sans GB, now using 300`** 是自动加粗告警，不影响字体回退，**可忽略**。
8. **图内文字 / 图例的定位不要依赖 `ax.get_ylim()` 反算**（南沙册连栽两次）：直方图顶部标注按 `ax.get_ylim()[1]*0.88` 放，渲染后仍被裁。**正解是固定 `ax.set_ylim(0, N)` 给出明确余量，再用绝对坐标 + `ha/va` 定位**（标注宁可放到参考虚线左侧 `ha='right'`）。
9. **堆叠柱顶的数值标签会撞图例**：`ylim` 上界只比最大柱高一点点时（如 86 人配 `ylim(0,100)`），柱顶 `ax.text` 与 `ax.legend` 重叠。**把 `ylim` 抬到最大值的 1.35—1.45 倍并显式 `set_yticks`**（如 `ylim(0,122)` + `yticks([0,20,...,100])`），比挪图例省事。
10. **环形图中心数字被图例压住**：`center` 与 `bbox_to_anchor` 要一起调，且给足 `xlim` 余量。南沙册最终参数 `center=(-1.05,0)` + `set_xlim(-2.15, 2.45)` + `legend bbox_to_anchor=(0.575, 0.5)`。
11. **`.fig` 的默认宽度与修饰类必须分成两个 CSS 块**：写在同一块里（`.fig img{width:100%}` 紧接 `.fig.w64 img{width:64%}`）会让修饰类失效——**默认宽度要独立成块**，修饰类再各自成块。
12. **每个用到的宽度类都必须在 CSS 里有定义，否则静默回落为全宽**（汕头基层服务岗册踩到）：HTML 写 `class="fig w82"` 但 CSS 只定义了 `w80/w88/w74/w66/w56` 时，该图会回落到 `.fig img{width:100%}` 变成**全宽**——图反而变大、溢出加剧，而"调小宽度"的意图完全落空。症状是**改小宽度后溢出值不降反升**。正解：**预先定义一整排宽度类**（`w56 w62 w66 w70 w74 w78 w80 w82 w86 w88`），不要临时发明。**此坑已第二次踩到**（广州辅警册用未定义的 `w64`，导致 P04 溢出在 77/52/24/106px 之间反复跳、改小宽度反而变大）。**开工第一步就把这一排宽度类写进 `style.css`，不要等溢出再补。**
13. **柱状图上的"转折点注释"要放到柱顶之上的留白区，不要贴在柱子旁边**（珠海市局册踩到）：原来把 `ax.annotate` 的文本放在柱子右侧 `y=57`、箭头指向 `y=62`，结果与 60% 的柱顶标签**完全重叠**。正解是**抬高 `ylim`**（60 的柱子配 `ylim(0,100)`），文本放到 `y=89` 的空白带、箭头向下指向柱顶 `xy=(2.17, 64.5)`——比挪图例、缩字号都干净。同时**删掉图内图例文字**，改在 `.fig-cap` 里写明"深蓝＝笔试权重，橙色＝面试权重"。
14. **图内标题不要与页面 `h3` 重复**：若小节标题已写"项目演变：长跑退场，平板支撑登场"，图内标题就改成中性的"XX 演变（2021—2026）"，否则同一句话在一页里出现两遍。

### 工程类
1. **`inspect.py` 与 Python 标准库冲突** → `AttributeError: partially initialized module 'openpyxl' ... circular import`。**别用 inspect / json / types 等标准库名当脚本名**。
2. **同一文件的多个 Edit 必须串行提交**：一条消息里并行发多个 Edit 会丢失更新（后写覆盖先写）。
3. **`rm` 会被 safe-delete 拦截**：在 `A && rm -f x && B` 链中 rm 被拦会使 B 静默不执行 → 转换 PDF 时不要串 rm，让 Edge 直接覆盖同名文件。
4. **管理包隔离**：为本套技能单建一个 venv 并只往里装包，不要污染系统环境。
5. **改完图表必须重跑 build 脚本**：build 读的是 `build/charts/`，而单独重制图表时常写回 `charts/` → **不同步且不报错**，PDF 里还是旧图。南沙册靠 `md5` 对比才发现。每次改图后跑一遍完整 build（内含 `copytree`），再 `md5` 抽查。
6. **招聘平台接口的分页参数必须逐个探测**：南沙优聘用 `pageNum`/`pageNo`/`current`/`pageSize`/`size`/`limit`/`rows` **全部无效**（永远返回第 1 页），正解是 `page=N`。探测法：连发两次不同参数值，比对返回的 `page` 字段与首条 id 是否变化。
7. **`pypdfium2` 别名别写错**：`import pypdfium2 as pdfium` 之后调用必须是 `pdfium.PdfDocument(...)`，写成 `pdfium2.PdfDocument` 会 `NameError`。
8. **`rm -rf /tmp/xxx` 单独执行**：与 `ls`/`echo` 串在一条命令里曾整条被 SIGTERM(137) 中断（目录未删成）；拆成独立命令即成功。
9. **长列表 / 长脚本一律 `Write` 成 `.py` 再执行**：heredoc 内联复杂 Python 会被安全策略拦截。
10. **图表同步必须放在"每次都会跑"的合并脚本里，不能只放在某个 part 的 build 里**（珠海拱北口岸册踩到的最隐蔽的坑）：`build/charts/` 一旦丢失，PDF 里所有图**静默变空白**，而**溢出检测返回 none、填充率反而更"正常"**（页面变矮更不容易溢出）——机器巡检全部通过，只有逐页目检才发现。**正解：把 `shutil.copy(charts → build/charts)` 写进 `merge.py`，每次合并强制执行并打印同步数量。**
11. **Edge 转 PDF 必须带 `--virtual-time-budget=15000`**：不加时 SVG 可能来不及解码，同样静默出空白图（与第 10 条症状相同、成因不同，两条都要防）。
12. **Python f-string 里禁止出现 ASCII 直引号**：中文正文中的引号一律用全角 `“ ”`，否则报 `SyntaxError: invalid character '，' (U+FF0C)`——**报错行号会指向下一个非 ASCII 字符**，极难定位。写完先跑一次 `ast.parse(src)` 做语法预检。
13. **分小节编号后必须全局 grep 一遍重号**：珠海册第 4 页误用了与第 3 页相同的 `1.3`，目录也对不上。改编号时同步改**三处**：正文小节号、目录条目文字、目录页码。
14. **附录长表：把"共性条件"抽出成 note，表内只留差异项**：9 行岗位表每行重复同一段 90 字条件 → 抽出后 P23 从溢出 316px 降到 87.2% 填充率。这比删列、缩字号都干净。
15. **封面中部留白用"数据条"填，不要拉大字号**：`.cover-stats` 四格（累计投放 / 权重比 / 学历门槛 / 薪酬口径）既能填满纵向空间，又等于把全册结论前置到封面。
16. **封面署名的 `letter-spacing` 不要超过 `.15em`，否则合规 grep 会漏检**（珠海市局册踩到）：`.cover-org{letter-spacing:.30em}` 会让 PDF 文本抽取把「广东中公教研」拆成「广 东 中 公 小 红 书 运 营 部」，导致「中公」计数从应有的 24（封面 1 ＋ 页脚 23）掉到 23。**症状**：视觉上完全正常，只有跑文本抽取才发现对不上。降到 `.14em` 即恢复正常。改完必须重跑「中公次数 == 页数」这条校验。
17. **填充率脚本若带 PNG 缓存判断（`if not os.path.exists(png)`），改版后必须手动清 png 目录**（珠海市局册踩到）：`check_fill.py` 这类脚本为了省时间会跳过已存在的 PNG，结果**改完 HTML 重新渲染 PDF 后，填充率数字纹丝不动**（P02 补了内容仍显示旧的 52.6%），会让人误判"修改无效"。正解：`rm -rf build/png` 后再跑，或把渲染改成无条件覆盖。
18. **`break-after:page` 必须和 `page-break-after` 一起复位**（系列册踩到）：只写 `.page:last-child{page-break-after:auto}` 时，`.page` 上并存的 `break-after:page` 仍然生效 → **末页后多出一张空白页**，PDF 页数比 div 数多 1。两者都要写 `auto`。
19. **"全册页数"要把封面算进去**：页序变量 `pn` 的终值是最末一页的**页码**（封面不编号），实际页数 = `pn + 1`。系列册第一版在封底印了 15 页而 PDF 实际 16 页，就是漏了封面。
20. **Edge 无头在沙箱里会静默失败，批量循环必须校验产物**（系列册踩到，代价是白等 3 分钟）：沙箱下 Edge 报 `Failed to initialize sandbox` / `GPU process isn't usable. Goodbye.` 后直接退出，**不写 PDF**；而 `for K in ...; do edge ...; echo "$K done"; done` 会把 9 个 `done` 全打出来，只有靠 `ls out.pdf` 才发现只有第一册是上一次的旧文件。正解三条：① 命令加 `--no-sandbox --disable-dev-shm-usage`；② 循环里用 `[ -f "$D/out.pdf" ] && echo OK || echo MISSING` 代替 `echo done`；③ 前台执行（后台运行拿不到沙箱豁免）。
21. **多册批量时，图表必须"每册独立目录"**（`charts/<key>/`）：九册共用一套图表函数但输出到各自目录，`build.py` 里 `copytree` 到 `build/<key>/charts/`。否则后一册的图会覆盖前一册，症状是九册图表内容串味（且溢出/填充率巡检完全看不出来）。
22. **"文件存在就用它"的选图逻辑会被上一轮残留骗到**（系列册踩到，浪费两轮重渲）：为中山写了「无人数口径 → 改用 `ratio.svg`」的分支后，`build.py` 用 `os.path.exists(charts/<key>/scale.svg)` 判断，**上一轮生成的 `scale.svg` 还在目录里** → 依旧选中旧的单柱图，而 PDF 体积几乎不变、溢出/填充率也正常，只有逐页目检才看出来。正解：**每轮重制图表前先删掉可能过期的候选文件**（`for stale in ('scale.svg','ratio.svg'): os.remove(...)`），别靠"存在性"做分支。
23. **批量渲染脚本删掉目标 PDF 再跑**：`[ -f out.pdf ]` 判成功对**上一次的旧文件**同样为真。最稳的是渲染前 `rm -f build/*/out.pdf`，渲染后逐个校验存在性与 `md5`（两次渲染同输入 md5 必须相同，不同就说明改了东西却没生效）。
18. **表格通用函数不能用「元组」区分整行高亮**（珠海市直教师册踩到）：`isinstance(r, tuple)` 会把**普通的多列元组行**误判为 `(cls, cells)`，于是 `cells` 变成第二列的字符串并被逐字符迭代，整张表炸掉且不报错。**正解：用 dict `{"cls":"hl","cells":(...)}` 标记高亮行，普通行保持 list/tuple。**
19. **附录宽表用 `<colgroup>` 定列宽**（珠海市直教师册）：`table(..., widths=["15%","11%","7%","47%","20%"])` 可根治「人数」被折成「人 数」、「高中语文」被折成「高中 语文」这类表头折行——比缩短表头文字更彻底，也不用动全局 CSS。
20. **政务站公告 404 时先换栏目前缀**（珠海市直教师册）：珠海市教育局同一 post id 在 `/zwgk/gsgg/` 下 404、换 `/ywgz/jsdw/` 即通；`www.zhuhai.gov.cn` 镜像常保留旧页。**同一公告页的附件编号不连续**（442036/442037/442039/442040/**442308**），必须按 HTML 里的附件名称逐个映射，不能按编号顺序猜。
   > **广州公安口径补充（2026-09 实测）**：`gaj.gz.gov.cn` 公告页会出现**「搜索引擎已收录、实际 curl/WebFetch 均 404」**的情况（`/zwdt/tzgg/content/post_11014071.html`），且**同 post id 换栏目前缀（`/jmhd/zjzq/2019nzjxx/`）同样 404** —— 此时不要再试前缀，直接**走转载页**：用 WebFetch 读转载页正文拿全文，再从正文 HTML 里提取附件真实直链（本次拿到 `hera.fbstatic.cn/469230384257024.xlsx` 岗位表）。**附件直链规律**：`gaj.gz.gov.cn/attachment/0|7/{目录}/{文件}/{post_id}.{ext}`，**必须带 `Referer`** 才能下。
21. **下载失败的最快识别法**：多个不同 URL 下载到**完全相同的字节数**（实测 11 542 字节）就是被统一重定向了。华图附件镜像 `gd.huatu.com/z/go/u3/?u=...` 已全部失效（302 到落地页），历年职位表改走官方站或其他转载站。
22. **给图表加注释前先算 `ylim` 余量**（珠海市直教师册）：横向条形图的"均值线"注释若放在末行（`y=11.55`）会被条形压住。正解是**显式 `set_ylim(n-0.45, -1.05)` 并把注释放到首行之上**（`y=-0.80`），不要依赖 `invert_yaxis()` 后的自动范围。
23. **加内容会立刻溢出，修法按此顺序最省事**（珠海市直教师册实测）：把独立的 `note` 容器**降级为普通段落**（省 ~15mm）→ 精简长 note（每行 ~5.5mm）→ 删表格行（每行 ~7mm）。比调 CSS 全局密度快得多。


### 修法优先级
**全局收紧密度 > 分拆章节 > 内容搬家 > 删内容 > 拉伸留白**

- **全局收紧密度**：溢出页 ≥8 页时，先做一轮全局 CSS 微调（行高、列表 padding、单元格 padding、章标题 margin 各收 0.1—0.5mm），往往一次消掉大半溢出。南网册 25 处替换把 12 页溢出降到 3 页。
- **分拆章节**：单页溢出 >300px 时，把该章**拆成两章**比删内容优雅得多——内容自然分流，还能把此前闲置的图表用上。南网册第 21 页溢出 404px，拆"录取画像"为两章即解。
- **内容搬家**：某章结尾溢出 1—3 行导致下页几乎空白时，把**另一章有空档的小节整段搬来**（改编号即可），一次同时修好"溢出页"和"偏空页"，且不损失内容。
- **删内容**：仅在内容确实冗余时（表格已承载同一信息的那张图）。
